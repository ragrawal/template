## Why

`adopt-generic-bdd-steps` established a `tests/bdd/` pattern for writing pytest-bdd suites in this repo: literal, runnable commands in Gherkin text, a small set of generic reusable steps, and step-decorators living directly on shared "action module" functions rather than one bespoke function per scenario. Downstream projects generated by this template start with no BDD testing convention at all (just a placeholder `pytest` test), and no documented way for an AI coding assistant to write BDD-style tests correctly — including a non-obvious pytest-bdd registration gotcha this repo's own suite had to work around. Shipping the same scaffold and a skill documenting the convention lets every generated project start from a working, correctly-wired example instead of everyone re-discovering the registration gotcha independently.

## What Changes

- Add `pytest-bdd` to the dev dependency group in `template/pyproject.toml.jinja`.
- Add a `tests/bdd/` scaffold to every generated project: `tests/bdd/actions/{shell,files}.py` (generic, reusable step definitions - temporary directory, run command, assert exit code/output, assert files exist/contain text), `tests/bdd/conftest.py` (registers the action modules via wildcard import, no `__all__`, no `pytest_plugins`), and a minimal example feature (`tests/bdd/example/example.feature` + `test_example.py`) demonstrating the convention against the generated package itself.
- Add `tests/__init__.py` to the template so `tests` is a regular importable package (required for the `tests.bdd.actions.*` absolute imports to resolve).
- Add a new bundled assistant skill, `.claude/skills/write-bdd-tests/SKILL.md`, to every generated project, documenting the `tests/bdd/` directory structure, the generic step vocabulary, the action-module pattern, and the pytest-bdd registration gotcha (and its fix) - mirroring the equivalent skill added to this repo at `.claude/skills/write-bdd-tests/SKILL.md`.

## Capabilities

### New Capabilities
(none)

### Modified Capabilities
- `template-generation`: generated projects must additionally include a `tests/bdd/` scaffold (action modules, conftest registration, example feature) and the `pytest-bdd` dev dependency.
- `ai-agent-guidance`: every generated project must additionally include a bundled, functional `write-bdd-tests` assistant skill.

## Impact

- **Changed**: `template/pyproject.toml.jinja`, new files under `template/tests/bdd/`, `template/tests/__init__.py`, new `template/.claude/skills/write-bdd-tests/SKILL.md.jinja`.
- **Possibly changed**: `tests/bdd/template_generation/template_generation.feature` in this repo, if a new scenario is added asserting the generated project ships the scaffold and skill (mirroring the existing "ships AI agent guidance and a quality-check skill" scenario).
- **Unaffected**: this repo's own `adopt-generic-bdd-steps` suite rewrite (already complete); the push-triggered CI workflow.
